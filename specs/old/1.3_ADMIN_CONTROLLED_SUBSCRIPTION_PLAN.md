# 1.3 Admin-Controlled Subscription Engine Implementation Plan

## Overview
This plan replaces the config-driven subscription approach with a fully admin-controlled, area-aware subscription system as required by PROJECT.md. The system allows administrators to dynamically create, manage, and price subscription plans per operational area without hardcoded configurations.

---

## 1. Architecture Principles

### 1.1 Admin-First Design
- **No hardcoded plans**: All subscription plans created through admin interface
- **Dynamic pricing**: Area-specific pricing set by administrators
- **Live management**: Plans can be created, modified, activated/deactivated in real-time
- **Area-aware**: Different plans and pricing for different operational areas

### 1.2 Key Differences from Previous Approach
**❌ Old Approach (Config-Driven):**
- Hardcoded tiers in migration files
- Fixed USD pricing
- Configuration-based plan definitions
- Single global pricing model

**✅ New Approach (Admin-Controlled):**
- Admin creates plans through management interface
- Area-specific pricing in local currencies
- Dynamic plan management
- Area-aware subscription model

## 3. Database Schema

### 3.1 New Tables

#### subscription_plans
```sql
CREATE TABLE subscription_plans (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name VARCHAR(100) NOT NULL,
    code VARCHAR(50) NOT NULL UNIQUE,
    description TEXT,
    features JSONB NOT NULL DEFAULT '{}',
    limits JSONB NOT NULL DEFAULT '{}',
    trial_days INTEGER DEFAULT 0,
    sort_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    created_by UUID NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

#### plan_area_pricing
```sql
CREATE TABLE plan_area_pricing (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    plan_id UUID NOT NULL REFERENCES subscription_plans(id) ON DELETE CASCADE,
    area_id UUID NOT NULL, -- References areas from core service
    monthly_price DECIMAL(10,2) NOT NULL,
    annual_price DECIMAL(10,2) NOT NULL,
    currency VARCHAR(3) NOT NULL DEFAULT 'USD',
    is_active BOOLEAN DEFAULT true,
    created_by UUID NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),

    UNIQUE(plan_id, area_id)
);
```

#### Enhanced subscriptions
```sql
ALTER TABLE subscriptions
ADD COLUMN plan_id UUID REFERENCES subscription_plans(id),
ADD COLUMN area_id UUID NOT NULL,
ADD COLUMN pricing_id UUID REFERENCES plan_area_pricing(id);
```

#### Plan Creation Request
```go
type CreatePlanRequest struct {
    Name        string                 `json:"name" validate:"required,min=3,max=100"`
    Code        string                 `json:"code" validate:"required,min=2,max=50,alphanum"`
    Description string                 `json:"description" validate:"max=500"`
    Features    map[string]interface{} `json:"features" validate:"required"`
    Limits      map[string]int         `json:"limits" validate:"required"`
    TrialDays   int                   `json:"trial_days" validate:"min=0,max=90"`
    SortOrder   int                   `json:"sort_order"`
}

type SetAreaPricingRequest struct {
    PlanID       uuid.UUID       `json:"plan_id" validate:"required"`
    AreaID       uuid.UUID       `json:"area_id" validate:"required"`
    MonthlyPrice decimal.Decimal `json:"monthly_price" validate:"required,min=0"`
    AnnualPrice  decimal.Decimal `json:"annual_price" validate:"required,min=0"`
    Currency     string          `json:"currency" validate:"required,len=3"`
}
```

## 8. Business Rules

### 8.1 Plan Management Rules

#### Plan Creation Rules:
- Plan codes must be unique across all areas
- Plans must have at least one area pricing to be active
- Trial days can be different per plan but same across areas for that plan

#### Pricing Rules:
- Each plan must have pricing for areas where it's offered
- Annual pricing must be less than or equal to 12x monthly pricing
- Currency must match the area's primary currency

#### Subscription Rules:
- Users can only subscribe to plans available in their current area
- Area changes don't automatically change subscription
- Plan upgrades/downgrades must respect area availability

### 8.2 Admin Permission Rules

#### Plan Management Permissions:
- Only super admins can create/delete plans
- Area admins can only set pricing for their areas
- Plan modifications require approval workflow for active plans
- Audit logging for all admin actions

## 9. User Experience Flow

### 9.1 User Subscription Flow

**Step 1: Plan Discovery**
```
User opens subscription page
↓
System detects user's current area
↓
Displays available plans for that area with local pricing
↓
User selects plan and billing cycle
```

**Step 2: Subscription Creation**
```
User confirms plan selection
↓
System validates plan availability in user's area
↓
Creates subscription with plan_id, area_id, and pricing_id
↓
Processes payment through area-appropriate gateway
↓
Activates subscription
```

**Step 3: Area Change Handling**
```
User moves to new area
↓
System detects area change
↓
Checks if current plan is available in new area
↓
If available: Continues subscription
If not available: Suggests alternative plans
```

### 9.2 Admin Management Flow

**Step 1: Plan Creation**
```
Admin creates new plan with features and limits
↓
Sets plan availability status
↓
Plan is created but not available to users yet
```

**Step 2: Pricing Configuration**
```
Admin selects areas where plan should be offered
↓
Sets monthly/annual pricing for each area
↓
Configures currency for each area
↓
Activates pricing for areas
```

**Step 3: Plan Activation**
```
Plan becomes available to users in configured areas
↓
Users can see and subscribe to the plan
↓
Admin monitors adoption and can adjust pricing
```
