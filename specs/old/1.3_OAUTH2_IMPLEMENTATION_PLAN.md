# 1.3 OAuth2 Integration Implementation Plan

## Overview

This document outlines the implementation plan for OAuth2 integration (Google and Facebook) in the MyTorra core service. The implementation follows the mandatory service guidelines, clean architecture principles, and includes comprehensive testing at all layers.

## Architecture Alignment

### Service Guidelines Compliance
- **Clean Architecture**: Following domain → application → adapters layer structure
- **i18n Support**: All user-facing messages translated
- **Context Keys**: Typed keys for OAuth-related context values
- **Error Handling**: Using shared error package with proper wrapping
- **Testing**: Unit, integration, and handler tests for all components
- **Security**: Secure token handling, PKCE flow, state validation

### Reference Implementation
Based on existing core service patterns:
- Auth handler pattern: `services/core/internal/adapters/http/handlers/auth_handler.go`
- User entity with OAuth fields: `services/core/internal/domain/entities/user.go`
- Repository pattern: `services/core/internal/adapters/postgres/repositories/user_repository.go`
- Service orchestration: `services/core/internal/application/services/auth_service.go`

## 2. Database Schema

### 2.1 New Tables Migration

```sql
-- migrations/005_create_oauth_profiles.up.sql
CREATE TABLE oauth_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    provider VARCHAR(50) NOT NULL,
    provider_id VARCHAR(255) NOT NULL,
    email VARCHAR(255),
    name VARCHAR(255),
    picture TEXT,
    access_token TEXT,  -- Encrypted
    refresh_token TEXT, -- Encrypted
    token_expiry TIMESTAMP WITH TIME ZONE,
    scopes TEXT[],
    raw_profile JSONB,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(provider, provider_id),
    INDEX idx_oauth_user_id (user_id),
    INDEX idx_oauth_provider_email (provider, email)
);

-- OAuth state table for CSRF protection
CREATE TABLE oauth_states (
    state VARCHAR(255) PRIMARY KEY,
    code_verifier VARCHAR(255),  -- For PKCE
    redirect_uri TEXT,
    provider VARCHAR(50) NOT NULL,
    ip_address INET,
    user_agent TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL
);

-- Cleanup expired states
CREATE INDEX idx_oauth_states_expires ON oauth_states(expires_at);
```

### 3.2 Port Interfaces

```go
// internal/application/ports/oauth_repository.go
type OAuthRepository interface {
    // OAuth Profile Management
    CreateOAuthProfile(ctx context.Context, profile *entities.OAuthProfile) error
    GetOAuthProfile(ctx context.Context, provider valueobjects.OAuthProvider, providerID string) (*entities.OAuthProfile, error)
    GetUserOAuthProfiles(ctx context.Context, userID uuid.UUID) ([]*entities.OAuthProfile, error)
    UpdateOAuthTokens(ctx context.Context, profileID uuid.UUID, accessToken, refreshToken string, expiry time.Time) error
    DeleteOAuthProfile(ctx context.Context, userID uuid.UUID, provider valueobjects.OAuthProvider) error

    // OAuth State Management (CSRF Protection)
    SaveOAuthState(ctx context.Context, state *valueobjects.OAuthState) error
    GetOAuthState(ctx context.Context, state string) (*valueobjects.OAuthState, error)
    DeleteOAuthState(ctx context.Context, state string) error
    CleanupExpiredStates(ctx context.Context) error
}

// internal/application/ports/oauth_provider.go
type OAuthProvider interface {
    GetAuthorizationURL(state, codeVerifier string) string
    ExchangeCode(ctx context.Context, code, codeVerifier string) (*OAuthTokens, error)
    GetUserProfile(ctx context.Context, accessToken string) (*OAuthUserProfile, error)
    RefreshToken(ctx context.Context, refreshToken string) (*OAuthTokens, error)
    RevokeToken(ctx context.Context, token string) error
}

type OAuthTokens struct {
    AccessToken  string
    RefreshToken string
    ExpiresIn    int64
    TokenType    string
    Scopes       []string
}

type OAuthUserProfile struct {
    ID       string
    Email    string
    Name     string
    Picture  string
    Verified bool
    Raw      map[string]interface{}
}
```

## 7. Security Considerations

### 7.1 PKCE (Proof Key for Code Exchange)
- Generate code_verifier and code_challenge for each OAuth flow
- Store code_verifier with state for validation
- Include code_challenge in authorization request
- Validate code_verifier during token exchange

### 7.2 State Parameter (CSRF Protection)
- Generate cryptographically secure random state
- Store state with expiration (10 minutes)
- Validate state on callback
- Delete state after use

### 7.3 Token Security
- Encrypt tokens before storing in database
- Use secure key management (Vault/Secrets Manager)
- Implement token rotation on refresh
- Revoke tokens on account unlink

### 7.4 Rate Limiting
- Limit OAuth initiation requests per IP
- Limit callback attempts per state
- Implement exponential backoff for failed attempts
